That URL (`replay-5c1q1qihi-zaryabk11s-projects.vercel.app`) is a **per-deployment preview URL** (the random hash is the deployment ID), not your stable production domain `replay-ai-mauve.vercel.app`. Those preview URLs get torn down/rotate, which is exactly why Inngest "can't reach" it now. This typically happens when a sync fired from a preview/branch deploy rather than production.

To fix it:

1. **Re-sync against the correct production endpoint.** In the Inngest dashboard, go to your app → there should be a "Sync new app" / manual sync option — point it at:
   ```
   https://replay-ai-mauve.vercel.app/api/inngest
   ```
2. **Check the Vercel ↔ Inngest integration** (Vercel project → Settings → Integrations → Inngest). If you installed the official integration, verify it's configured to sync on **Production** deployments (not every preview). If it's syncing previews too, that's how the bad URL got registered.
3. **Check Vercel Deployment Protection** (Settings → Deployment Protection). If protection/password is on for production, Inngest's sync requests to `/api/inngest` will fail the same way — it needs unauthenticated access to that route.
4. **Clean up the stale entry** — once the correct sync succeeds, you can delete/ignore the old "Unattached Sync" error row; it's just a record of the failed attempt against the dead preview URL.
